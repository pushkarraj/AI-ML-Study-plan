04b 9 Latency Optimization Techniques — Har Millisecond Ka Hisaab

Without optimization: 815ms. With: 120ms. 6.8x improvement. Har technique ka contribution:

1. Anycast DNS + Cache
2ms (fallback: 5ms)
Ek IP, sabse paas ka server respond kare. Client DNS cache = 0ms repeat. Jaise toll-free number — nearest call center uthata hai.
2. Edge PoP Same City
3ms (fallback: 10ms)
TLS handshake user ke paas (PoP) pe hota hai, not distant server. Mumbai→Virginia = 200ms, Mumbai→Mumbai PoP = 2ms.
3. gRPC (Binary Protocol)
5ms (REST: 15ms) — saves 10ms
Protobuf binary = 58% chhota JSON se. HTTP/2 multiplexing = 100 requests ek connection pe. Google internally sab gRPC pe.
4. DAX In-Memory Cache
<1ms (DDB direct: 15ms) — saves 14ms
DynamoDB ke aage RAM cache. 95% hit rate. Microwave vs oven — dono garam karte hain par microwave instant. $10.5K/mo saves $700K/mo.
5. DistilBERT Intent (Not LLM!)
2ms (LLM: 200ms) — saves 198ms (BIGGEST WIN)
66M params vs GPT-4 1.7T. CPU pe chalta hai, GPU nahi chahiye. 95% accuracy. Ant uthane ke liye crane nahi chahiye.
6. Parallel Memory Retrieval
7ms (sequential: 9ms)
Redis (0.5ms) + Bigtable (3ms) + Milvus (5ms) = parallel max = 5ms + 2ms merge. Teeno ek saath, wait for slowest.
7. vLLM + Speculative Decode
100ms (API: 500ms+) — saves 400ms+
Self-hosted = no network hop. PagedAttention = 10x concurrent/GPU. Draft model 5 tokens → target verify batch → 2.5x speedup.
8. Persistent WebSocket
7ms (new conn: 45ms)
Connection ek baar open, reuse karo. No TLS re-handshake. Token batching: 3-5 tokens per 50ms = 4x less network frames.
9. Safety Buffer (Jitter)
8ms reserved for variance
P99 tail latency absorption. Network jitter, GC pauses, kernel scheduling. Hedged requests for outlier elimination (Google "Tail at Scale" paper).

Resilience Techniques
Replication: 3 replicas per shard, auto-failover <5s
Circuit Breaker: CLOSED→OPEN→HALF_OPEN, prevents cascading
Retry + Backoff: exponential (100→200→400ms) + jitter
WAL: Write-Ahead Log = zero data loss on crash
Chaos Engineering: Monthly game days, kill regions deliberately
Graceful Degradation: Redis miss→DAX→DDB→cached→FAQ→error page
Sharding Strategies
Hash-Based: uniform, no range queries. Redis sessions.
Consistent Hashing: add shard = 1/N rehash (not all). 150 vnodes.
Range-Based: time-series scan fast. Bigtable row keys.
Tenant/Directory: single-shard queries. Milvus vectors.
Partitioning: Horizontal (row split, 225x faster queries) · Vertical (column split, 17x less I/O) · Functional (6 DBs, polyglot)
CAP Theorem: Redis = CP (consistent, partition tolerant). DynamoDB cross-region = AP (available, eventual). Same-region DynamoDB = CP (strong consistency). Bigtable = AP. PACELC: latency is king → EL preference for most reads.

04d LLM Inference Optimization Stack — 6 Techniques

vLLM + PagedAttention
GPU memory ko pages mein manage. Naive: 40 concurrent/GPU. vLLM: 400 concurrent/GPU (10x). Hotel room analogy — sirf utne rooms do jitne chahiye, pehle se reserve nahi.
Throughput: 3-5x improvement
Speculative Decoding
7B draft → 5 tokens (10ms). 70B verify batch (20ms). 5 tokens in 30ms vs 100ms. Junior draft likhta hai, senior ek baar review. 75% acceptance rate.
Speed: 2.5x faster generation
Continuous Batching
Request khatam → turant hataao, naya daalo. Bus analogy — passenger utra? Turant naya bithao. Static: 200 tok/s/GPU. Continuous: 600 tok/s/GPU.
Throughput: 3-5x vs static batch
INT8 Quantization
32-bit → 8-bit weights. 140GB → 70GB. Memory-bandwidth bound → less data read = faster. Photo compression analogy — JPEG vs RAW, looks same.
Speed: 2x, Quality: 99% retained
Tensor Parallelism
70B model → 2 GPUs (70GB each). Parallel compute + NVLink AllReduce (0.1ms). 8 log milke heavy table uthayein. TP=2 sweet spot for 70B.
Speed: near-linear with GPU count
TensorRT-LLM + Kernel Fusion
3 GPU operations → 1 fused. 2 memory round-trips saved per fusion. 70B model = 800 ops/step → fusion saves ~16ms/decode. ECU tune jaisa.
Speed: 2-3x per-op improvement
Combined impact: Naive (no optimization): TTFT=500-800ms, 50 tok/s/GPU. All optimized: TTFT=50-100ms, 600 tok/s/GPU. 5-10x latency, 12x throughput. This is why $18M/yr works instead of $200M/yr.

06 Interview Quick-Fire Answers

"150ms kaise?" — (1) Self-hosted LLM, (2) DistilBERT intent 2ms not 200ms, (3) Model routing 7B/13B/70B, (4) Speculative decoding 2.5x, (5) DAX <1ms, (6) gRPC binary, (7) 150ms = TTFT not full response
"50M concurrent kaise?" — (1) 8 regions Anycast, (2) 500 Envoy 100K/node, (3) K8s HPA on connections not CPU, (4) 500-pod warm pool, (5) Redis 64 shards, (6) Global Tables, (7) Graceful degradation 3 levels
"Long-term memory kaise?" — (1) 5-tier pyramid, (2) Post-conv extraction (LLM+NER), (3) Ebbinghaus decay e^(-t/S), (4) Retrieve: recency×relevance×importance, (5) Bigtable 100TB $2.6K/mo, (6) GDPR right-to-forget, (7) $0.0016/user/year
"Cost kitna?" — Original $43M/yr → Optimized $18M/yr (Spot 60% + Reserved + Model routing). ₹1.5/user/year. GPU 61% of cost — model routing saved $45M/yr.
"Security kaise?" — JWT (0.1ms verify, stateless) + mTLS (Istio service mesh) + DDoS (3-layer: CDN→Gateway→App) + Rate limiting (token bucket 10/sec/user, Redis distributed) + WAF
"Monitoring kaise?" — 3 pillars: Metrics (Prometheus+Grafana, RED+USE), Logs (ELK, structured JSON, 1% sampling), Traces (Jaeger/OTel, request journey). SLO: P99 TTFT <150ms, 99.95% availability, error budget = 0.1%
"Deploy kaise safely?" — Canary: 1%→10%→50%→100% with auto-rollback (Flagger). ArgoCD GitOps. Feature flags for instant enable/disable. Blue-green for zero-downtime DB migrations.
